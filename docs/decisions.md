| D52 | **Amends D41: render on NVIDIA when an external monitor is on its ports** (MH, 2026-10-18). | D53 (**rendering order amended by D59**) | **Amends D52: on zbook, always open the NVIDIA card, Intel renders; output layouts by kanshi** (MH, 2026-10-21). Intel-first because it leaves the NVIDIA 3D engine and most of its 4 GB free for compute (NVIDIA only scans out copied frames) and because NVIDIA-first left the laptop panel black under SwayFX (`Failed to allocate buffer, no swapchain`, 2026-10-21). `prefer_nvidia_for_external` stays as the experiment switch. | D54 | **One shared save-path prompt, `~/.local/bin/pick-path`, for every widget that writes a file** (MH, 2026-10-22). A standalone CLI (Python, stdlib only, so it runs from a keybinding without a venv), not a sourced Bash library: any script in any language calls it and gets a checked absolute path on stdout (exit 1 cancelled, 3 refused). Rules: a name or relative path goes under the caller's `--base` (directories created); `~/` and absolute paths as given; `--ext` is added to an extensionless name and other extensions are refused (upload pickers and chat apps filter by extension); an existing file is overwritten only after a confirmation prompt, anywhere; a path that would need sudo is refused with a notification, never escalated. First caller: `screenshot`. A read-side (open-file) variant is not built until a widget needs it. |
| D59 | **Amends D53: NVIDIA renders SwayFX sessions that start docked; the laptop panel is unusable in them** (MH, 2026-10-23). The panel cannot be lit while NVIDIA renders: its mode set fails, and `WLR_DRM_NO_MODIFIERS=1` blacked out every output (2026-10-23). Costs: no panel while docked; undocking mid-session leaves no screen until re-docking or a new login (undocked logins render on Intel, panel included); NVIDIA at P5, ~8 W instead of ~2.7 W. Next: the Hyprland trial for smoothness *and* the panel (plan). GNOME stays the fallback for calls. |
| D60 | **Hyprland renders on Intel, docked too; D59 stays for SwayFX only** (MH, 2026-10-23). Reasons: it leaves the NVIDIA card free for compute work, and it costs nothing measurable: `sway-perf` mouse 14.5% avg Intel-first vs 21.3% NVIDIA-first, hands off 1.5% vs 0.3%, MH felt no difference (one run each, compositor CPU only; GPU load not measured), unlike SwayFX's software cursor at 42%. Hyprland lights the panel either way. MH prefers Hyprland so far (and its Lua config, familiar from Neovim). The first stated reason, avoiding the NVIDIA resume bug, was **refuted** by the Intel-first suspend series (the `semsurf` error and black externals happened Intel-first too; D61). Implemented 2026-10-23: `~/.config/uwsm/env-hyprland` puts Intel first by default; host key `hyprland_render_gpu` (`intel`/`nvidia`) for re-tests. |
| D61 | **No suspend while docked** (MH, 2026-10-23; interim, until the NVIDIA driver or a workaround fixes resume). Resuming with external monitors active blacked out the externals (Hyprland Intel-first: 3 of 3 resumes) or broke NVIDIA-rendered clients (SwayFX: 2 of 7), and a replug after one such resume wedged NVIDIA's display engine (`Flip event timeout on head 1`), freezing the display stack and VT switching (hard reboot; the kernel kept running). Undocked resumes were fine. `dock-awake suspend` and the power key refuse while docked, with a notification to unplug the monitors first; the only docked suspends left are battery last resorts (AC lost while docked and locked, after the grace; swayidle's idle suspend on battery), each with a critical warning, and every docked resume leaves a persistent notice and a journal warning. **Power key (same night):** logind ignores a short press (the compositor binding refuses docked, suspends undocked; no session lock on `handle-power-key`). A long press cannot be a clean power off on zbook (the ACPI button reports instant press/release; HP's firmware cuts power at ~5 s), so the clean way out of a wedged display is SysRq REISUB (`kernel.sysrq = 244`). Rejected for now: turning the externals off before suspend and back on after (scope and risks in [plans/wayland-desktop.md](plans/wayland-desktop.md), "Docked suspend workaround"; after the driver upgrade). |

| D64 | **`dock-awake` holds logind's `handle-lid-switch` lock whenever docked, on AC or battery** (MH, 2026-10-23; amends D61). ## Hardware and security

| # | Decision |
|---|---|
| D34 | scdaemon reaches the YubiKey **through pcscd in shared mode** (`disable-ccid` + `pcsc-shared` in `~/.gnupg/scdaemon.conf`), rendered only on hosts where pcscd is installed (MH, 2026-10-17). Reason: once pcscd runs it owns the CCID interface, and gsd-smartcard and Chromium keep the card open, so the built-in driver and an exclusive connect both fail. Rejected: exclusive mode with gsd-smartcard and Chromium's card access disabled (loses lock-on-removal, Chromium's holder is hard to pin down).
